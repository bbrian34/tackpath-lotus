Lotus OS
Exploring what it takes to turn TackPath Lotus from a managed dispatch tier into a full courier service operating system — one where AI agent pods run dispatch, fleet, billing, CRM, and revenue intelligence together, coordinated through a single workspace where humans retain approval authority.
The shift from alerting to acting, with humans in the loop.

Build Phases
01
Supabase MCP Proof of Concept
Connect Claude directly to the TackPath Supabase database via the official MCP server. Verify that an agent can query real job data, real driver locations, and real exception history using natural language. Read-only, scoped to the TackPath project. This is the data foundation everything else depends on.
Building now
02
Exception Intelligence Agent (real data)
Rebuild exception detection (Late, Unassigned, Driver Dark) as a real agent using the Supabase MCP connection. Same logic as dispatcher.html, but the agent reasons over live data rather than a pre-fetched JavaScript array. Generate a real recovery plan with real driver options from the real roster.
After Phase 1
03
n8n Recovery Workflow
Wire the exception detection into an n8n workflow: detect exception → query available drivers → draft recovery messages → surface for human approval. The workflow engine that connects detection to action, visually and auditably, without touching production code.
After Phase 2
04
Twilio Integration
Wire Twilio into the n8n workflow so approved messages actually reach drivers and clients on their phones. Driver check-in SMS, client delay notification SMS. This is the step that makes everything above genuinely real rather than theoretical.
After Phase 3 · Twilio in progress separately
05
Buzz Integration
Wire the full workflow into a Buzz channel so detection, recovery plan, approval, and execution all happen in one shared workspace with full context and audit trail. Timing depends on Buzz reaching a stable 1.0 — pre-1.0 as of August 2026.
When Buzz hits 1.0
06
Full Lotus OS — Billing, CRM, OWL
Expand beyond exception recovery to cover the full courier service OS: OWL revenue intelligence, per-client margin flagging, draft invoice generation, client relationship signals, capacity planning alerts. All coordinated through the same workspace, all with human approval gates.
Phase 5 complete first
